## 1. 使用方式

1. **先起后端依赖**（推荐 Docker）：
   ```bash
   # 仓库根目录
   docker compose up -d
   # 需要 AI RAG 时再加：docker compose --profile milvus up -d
   ```
2. **配置并启动后端**（Java 21 + Spring Boot 4.1，端口 `8081`）：
   ```bash
   cp src/main/resources/application-local.yaml.example src/main/resources/application-local.yaml
   # 按 example 填 SMTP / JWT / AI Key；Docker 默认 DB root/root、Redis 无密码、MQ guest/guest
   mvn spring-boot:run -Dspring-boot.run.profiles=local
   ```
   表结构由 Flyway 自动迁移，无需手跑 SQL。
3. 打开本文 **§10 完整提示词**，整段复制到 AI 对话框。
4. 按需追加 §11（MVP / 完整版 / React / UI），生成后按 §9 验收。
5. 部署到服务器时对照 [前端部署指南](./前端部署指南.md)。

## 2.1 前端 UI 约束（生成时务必遵守）

避免千篇一律的「AI 默认皮肤」。生成页面时请：

- **品牌优先**：产品名「智慧书城」在首屏有明确存在感，不要只有顶栏小字
- **少用卡片堆砌**：列表/表单按业务分区；管理端可用表格，用户端首页不要仪表盘式一堆 stat 卡
- **避免**：紫白渐变、默认 Inter/Roboto 堆、满屏圆角 pill、多层阴影、emoji 装饰
- **用户端氛围**：书架 / 阅读空间感（浅色纸感或柔和木质/墨绿点缀即可），动效克制（2～3 处）
- **管理端**：清晰侧栏 + 内容区；看板用图表，不要花哨特效
- **响应式**：桌面与手机都能用；座位图在小屏可横向滚动

### 4.1 登录页交互要求

**密码登录 Tab**

- 字段：`account`、`password`、`rememberMe`
- 提交：`POST /api/auth/login`，`loginType: "password"`

**邮箱验证码 Tab**

- 字段：`target`（邮箱）、`code`、`rememberMe`
- 发码：`POST /api/auth/code/send`，`{ loginType: "qq_email_code", target, scene: "login" }`
- 60s 倒计时；验证码发邮件，**接口不返回明文**

**手机验证码 Tab**

- 字段：`target`、`code`、`rememberMe`
- 发码：`loginType: "phone_code"`（demo 环境无真实短信）

**QQ 扫码 Tab**

```text
1. GET /api/auth/oauth/qq/state → data: { state, appId, redirectUri }
2. 引入 QC.Login，参数使用后端返回的 appId / redirectUri / state
3. 页面展示二维码，用户手机 QQ 扫码确认
4. 浏览器跳转到后端 /callback，再 302 到前端：
   /oauth/qq/success#accessToken=...&refreshToken=...&expireIn=7200
5. success 页解析 hash，保存 Token 与 userInfo（可调 /me），跳转 /reservation 或 /profile
6. 失败页 /oauth/qq/error?reason=invalid_state|qq_oauth_failed|...
```

**登录成功（密码/验证码）**

- 保存 `accessToken`、`refreshToken`、`userInfo`（来自 login 响应）
- 跳转 `/reservation` 或 `/profile`

### 4.2 自习室预约页交互（精确到座位）

```text
1. GET /api/reservation/resources?page=1&size=10
2. 用户选择自习室 + 日期（DatePicker，格式 yyyy-MM-dd）
3. GET /api/reservation/resources/{id}/slots?date=2026-07-05
4. 展示时段列表：startTime-endTime、remainingCapacity
5. 用户点击某时段 → GET /api/reservation/slots/{slotId}/seats
   返回座位列表，含 rowNum/colNum 布局坐标、available（该时段是否可约）
6. 前端用 Grid 渲染座位图：
   - available=true  → 可点击（绿色/默认）
   - available=false → 已占用（灰色禁用）
   - status=0        → 座位停用（不展示或置灰）
7. 用户选中一个座位后点击「确认预约」→ POST /api/reservation/orders
   body: { timeSlotId, seatId, idempotencyKey? }
8. 成功提示 orderNo + seatNo，可跳转「我的预约」
```

**可选：仅预览座位布局（不区分时段占用）**

- `GET /api/reservation/resources/{id}/seats` — 返回全部座位，不含 `available` 字段

**我的预约**

- `GET /api/reservation/orders/mine?status=BOOKED&page=1&size=10`
- 列表/详情展示 **seatNo**（如 A01）
- 取消：`POST /api/reservation/orders/{id}/cancel`，body 可选 `{ reason }`
- 状态标签：BOOKED / CANCELLED / COMPLETED

#### 4.3.1 预约管理（`/admin/reservation`）

### 4.4 到馆签到页交互

```text
1. 用户扫描场馆二维码 → 打开 /checkin?venueId=1&code=A3K9M2
2. 未登录 → 跳转 /login?redirect=原 URL
3. GET /api/checkin/eligible?venueId=&code= → 展示 streak、todayCheckedIn、可签预约列表
4. todayCheckedIn=true → 提示今日已签，展示 streak
5. orders 为空 → 提示先预约今日座位
6. 用户选择一条 checkinable=true 的预约 → POST /api/checkin
   body: { reservationOrderId, venueId, code }
7. 成功：展示 streakDay；rewarded=true 时 Toast「获得优惠券」
8. /checkin/calendar → GET /api/checkin/calendar?month=2026-07 → 月历高亮 days 数组
```

**错误码**：4310 码无效 | 4301 今日已签 | 4302 无预约 | 4308 不在时段

### 4.5 图书、书架、购物车与借阅交互

```text
书架列表（可选筛选楼层）：GET /api/bookshelves?floor=
  → 用于详情页「附近书架」或管理端下拉；展示 floor + code

图书列表：GET /api/books?page&size&categoryId&keyword
  → 列表卡可展示 shelfLocation（有则可借找书）
图书详情：GET /api/books/{id}
  → 展示 price、saleStock、borrowStock
  → 有架位时醒目展示：bookshelfFloor、bookshelfCode、shelfLayer、shelfLocation
     文案示例：「取书位置：2楼 A-01 第3层」
加入购物车：POST /api/cart/items { bookId, quantity }  ← 同书多本用 quantity，重复加购合并为一行
购物车列表：GET /api/cart/items → 展示 subtotal、saleStock
改数量：PUT /api/cart/items/{id} { quantity }  ← quantity=0 删除
删除：DELETE /api/cart/items/{id}
申请借阅：POST /api/borrow/orders { bookId } → 状态 APPLIED
我的借阅：GET /api/borrow/orders/mine
  → 每条展示 bookTitle + shelfLocation（到馆取书导航）
  - APPLIED → 用户可 POST /api/borrow/orders/{id}/cancel
  - BORROWED / OVERDUE → 用户可 POST /api/borrow/orders/{id}/return
状态枚举：APPLIED | BORROWED | RETURNED | OVERDUE | CANCELLED
```

### 4.6 购书与优惠券交互（P3 购物车模式）

```text
我的优惠券：GET /api/coupons/mine?status=UNUSED

推荐购书流程（购物车）：
  1. 图书详情「加入购物车」→ POST /api/cart/items { bookId, quantity }
     同书买多本：quantity=3，或多次加购自动累加
  2. /cart 页展示列表，可勾选要结算的项（或默认全选）
  3. 计算选中项 subtotal 合计 → orderAmount
  4. GET /api/coupons/available?orderAmount=90.00 → 展示可用券与 estimatedDiscount
  5. 用户选券 → POST /api/trade/orders {
       cartItemIds: [1, 2],
       userCouponId?: number,
       idempotencyKey?: uuid
     }
  6. 展示 totalAmount / discountAmount / payAmount / status=PENDING_PAY
     → 建议展示「请在 15 分钟内完成支付」倒计时（基于 createdAt + 15min，或轮询订单状态）
     → 后端 MQ 延迟 15min 自动关单，超时后 status 变为 CANCELLED（无需前端调 cancel）
  7. POST /api/trade/orders/{id}/pay → 扣余额，刷新 /api/user/me 的 balance
  8. 下单成功后购物车对应项已清空；券在 pay 时才核销为 USED

  POST /api/trade/orders { bookId, quantity, userCouponId?, idempotencyKey? }

```

### 4.7 秒杀抢券交互（P4）


## 5. Token 管理（核心，必须实现）

### 5.1 存储策略

```text
accessToken   → sessionStorage（QQ 扫码从 hash 写入后同样存这里）
refreshToken  → localStorage
userInfo      → localStorage 或 Pinia
```

### 5.2 请求拦截器

- 受保护接口自动加：`Authorization: Bearer ${accessToken}`
- 公开接口可不加 Token，但 **`/api/ai/chat` 若本地有 Token 仍应带上**（否则个人借阅/个性化推荐无法识别用户）：
  - `/api/auth/login`、`/code/send`、`/refresh`、`/logout`
  - `/api/auth/oauth/qq/state`、`/api/auth/oauth/qq/callback`（浏览器跳转，非 axios）
  - `/api/ai/chat`（permitAll；有 Token 时主动附加）

### 5.3 响应拦截器（401 自动刷新）

```text
HTTP 401 且 body.code === 2002
  → POST /api/auth/refresh（text/plain，body 为 refreshToken 字符串）
  → 成功：覆盖双 Token，重试原请求
  → 失败 code=2001：清 Token，跳 /login

code=2003～2006 → 清 Token，跳 /login
HTTP 403 且 code=3001 → 提示无权限（鉴权层，非预约业务码）
```

### 5.4 Refresh 注意事项

- 每次 refresh **必须覆盖** accessToken + refreshToken
- 并发 401 用 Promise 锁，只 refresh 一次
- Body 是 **plain text**，不是 JSON

### 5.5 登出

```text
POST /api/auth/logout
Header: Authorization: Bearer ${accessToken}（可选）
Body: refreshToken（text/plain，可选）
→ 清本地 Token，跳 /login
```

### 5.6 QQ OAuth success 页解析 hash 示例

```typescript
const hash = window.location.hash.slice(1);
const params = new URLSearchParams(hash);
const accessToken = params.get('accessToken');
const refreshToken = params.get('refreshToken');
// 存入 storage 后 history.replaceState 清掉 hash，再 GET /api/user/me 或跳首页
```

### 6.4 错误码处理

#### 认证

| code | 前端处理 |
| --- | --- |
| 0 | 成功 |
| 1001 | Toast：账号或验证码错误 |
| 1002 | Toast：展示 `message`（限流/参数） |
| 2001 | 跳转登录 |
| 2002 | 尝试 refresh |
| 2003～2006 | 清 Token，跳登录 |
| 3001（HTTP 403） | 无权限（Spring Security） |

#### 预约业务（HTTP 200）

| code | 含义 | 前端处理 |
| --- | --- | --- |
| 3001 | 时段不存在 | Toast |
| 3002 | 名额不足 | Toast，刷新时段列表 |
| 3003 | 重复预约 | Toast |
| 3004 | 状态不允许 | Toast |
| 3005 | 无权操作 | Toast |
| 3006 | 超过每日预约上限（2 次） | Toast |
| 3007 | 自习室不存在 | Toast |
| 3008 | 预约单不存在 | Toast |
| 3009 | 时段已过期 | Toast |
| 3010 | 座位不存在或已停用 | Toast，刷新座位图 |
| 3011 | 该座位已被预约 | Toast，刷新座位图 |
| 5001 | QQ OAuth 未配置（仅 OAuth 相关接口） | QQ Tab 不可用 |

#### AI 客服（HTTP 200，`/api/ai/*`）

> 注意：AI 业务码与 QQ OAuth 的 `5001` 数字重叠，**按请求路径区分**：调 `/api/ai/chat` 时按下表处理。

| code | 含义 | 前端处理 |
| --- | --- | --- |
| 5001 | AI 服务暂不可用（模型空响应/上游异常） | Toast「稍后重试」，保留输入框内容 |
| 5002 | 请求过于频繁 | Toast 限流，短暂禁用发送 |
| 5003 | 会话不存在或已过期 | 清本地 `aiSessionId`，提示开启新会话 |
| 5004 | 参数错误（message 空/过长等） | Toast 展示 `message` |

#### 签到（HTTP 200）

| code | 含义 | 前端处理 |
| --- | --- | --- |
| 4301 | 今日已签 | 展示 streak |
| 4302 | 无预约 | 引导去预约 |
| 4308 | 不在时段 | Toast |
| 4310 | 码无效 | Toast，检查 URL |

#### 购书 / 借阅 / 图书 / 购物车（HTTP 200）

| code | 含义 | 前端处理 |
| --- | --- | --- |
| 4001 | 图书不存在 | Toast |
| 4002 | 可借不足 | Toast |
| 4003 | 有未还书 | Toast |
| 4005 | 分类不存在/已禁用 | Toast |
| 4006 | 书架不存在/已禁用（图书表单）或借阅单不存在 | Toast，刷新书架下拉 |
| 1002 message 含「可借图书须配置书架」 | 未配架位 | 引导选择书架与层数 |
| 4151 | 购物车项不存在 | Toast，刷新购物车 |
| 4152 | 无权操作购物车 | Toast |
| 4153 | 图书下架 | Toast |
| 4154 | 库存不足（购物车） | Toast，刷新库存 |
| 4155 | 购物车为空 | 引导去加购 |
| 4101 | 券不存在 | Toast |
| 4102 | 券不可用 | Toast，取消选券 |
| 4103 | 未达券门槛 | Toast，换券或不用券 |
| 4201 | 订单不存在 | Toast |
| 4202 | 订单状态不允许 | Toast |
| 4203 | 余额不足 | Toast |
| 4204 | 库存不足（下单/支付） | Toast |

#### 秒杀（HTTP 200）

| code | 含义 | 前端处理 |
| --- | --- | --- |
| 4251 | 已参与该活动 | Toast，禁止重复抢 |
| 4252 | 已售罄 | Toast，刷新 remainingStock |
| 4253 | 活动未开始或已结束 | Toast，刷新 activityPhase |
| 4254 | 活动不存在 | Toast，返回列表 |
| 4256 | 系统繁忙 | Toast，可重试（复用 idempotencyKey） |
| 4257 | 尚未参与 | 轮询页提示先抢券 |
