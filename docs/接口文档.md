# 接口文档

> 项目：`Factory_Test_Demo`
>
> 基础地址：`http://localhost:8081`
>
> 说明：本文档根据后端 `AuthController`、`DTO` 及相关服务逻辑整理，适用于前后端联调。

---

## 1. 通用说明

### 1.1 统一响应格式

所有接口均返回统一包装对象 `ApiResponse<T>`：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | 状态码，`0` 表示成功 |
| message | string | 提示信息 |
| data | object / array / null | 业务数据 |

### 1.2 常见错误码

| code | message | 说明 |
| --- | --- | --- |
| 0 | success | 请求成功 |
| 1001 | invalid credentials or code | 登录失败：账号密码错误或验证码无效 |
| 1002 | 具体异常信息 | 请求参数不合法 |
| 2001 | invalid or expired refresh token | Refresh Token 无效或已过期 |

### 1.3 登录类型 `loginType`

当前支持的登录方式：

| loginType | 说明 |
| --- | --- |
| `password` | 账号密码登录 |
| `qq_email_code` | QQ 邮箱验证码登录 / 邮箱验证码登录 |
| `phone_code` | 手机验证码登录 |

## 2. 接口列表

### 2.1 发送验证码

- **URL**：`POST /api/auth/code/send`
- **Content-Type**：`application/json`
- **用途**：向邮箱或手机号发送验证码

#### 请求参数

请求体使用 `SendCodeRequest`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| loginType | string | 是 | `qq_email_code` 或 `phone_code` |
| target | string | 是 | 邮箱地址或手机号 |
| scene | string | 是 | 场景，通常传 `login` |

#### 请求示例

```json
{
  "loginType": "qq_email_code",
  "target": "user@qq.com",
  "scene": "login"
}
```

#### 响应示例

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "expiresIn": 300,
    "code": "123456"
  }
}
```

#### 说明

- `expiresIn` 表示验证码有效期，单位：秒，当前为 **300 秒**。
- `code` 为验证码内容；项目中注明了 `demo only`，即仅演示环境可能返回明文验证码，生产环境不应直接返回。

---

### 2.2 登录

- **URL**：`POST /api/auth/login`
- **Content-Type**：`application/json`
- **用途**：支持密码登录、邮箱验证码登录、手机号验证码登录

#### 请求参数

请求体使用 `LoginRequest`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| loginType | string | 是 | 登录方式：`password` / `qq_email_code` / `phone_code` |
| rememberMe | boolean | 否 | 是否记住登录状态，默认 `false` |
| account | string | 条件必填 | 账号密码登录时必填 |
| password | string | 条件必填 | 账号密码登录时必填 |
| target | string | 条件必填 | 验证码登录时必填，邮箱或手机号 |
| code | string | 条件必填 | 验证码登录时必填 |

#### 2.2.1 账号密码登录示例

```json
{
  "loginType": "password",
  "account": "admin",
  "password": "123456",
  "rememberMe": true
}
```

#### 2.2.2 邮箱验证码登录示例

```json
{
  "loginType": "qq_email_code",
  "target": "user@qq.com",
  "code": "123456",
  "rememberMe": true
}
```

#### 2.2.3 手机验证码登录示例

```json
{
  "loginType": "phone_code",
  "target": "13800138000",
  "code": "123456",
  "rememberMe": false
}
```

#### 响应参数

返回 `ApiResponse<LoginResponse>`：

`LoginResponse` 字段如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| accessToken | string | 访问令牌 |
| refreshToken | string | 刷新令牌 |
| expireIn | long | 访问令牌有效期，单位秒 |
| userInfo | object | 当前登录用户信息 |

`userInfo` 字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | long | 用户 ID |
| username | string | 用户名 |

#### 响应示例

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "accessToken": "access:xxxxxxxx",
    "refreshToken": "jti:xxxxxxxx",
    "expireIn": 7200,
    "userInfo": {
      "id": 1,
      "username": "admin"
    }
  }
}
```

#### 业务说明

- 验证码登录成功后，验证码会被标记为已使用。
- 如果验证码登录对应的用户不存在，系统可能会根据目标账号自动注册。
- 密码登录采用用户名和密码校验。
- `rememberMe=true` 时，刷新令牌有效期更长；默认更短。

---

### 2.3 刷新 Token

- **URL**：`POST /api/auth/refresh`
- **Content-Type**：`text/plain`
- **用途**：通过 Refresh Token 换取新的 Access Token

#### 请求参数

请求体直接传入一个字符串，即 `refreshToken`。

#### 请求示例

```text
jti:xxxxxxxx
```

#### 响应示例

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "accessToken": "access:yyyyyyyy",
    "refreshToken": "jti:xxxxxxxx",
    "expireIn": 7200,
    "userInfo": {
      "id": 1,
      "username": "admin"
    }
  }
}
```

#### 说明

- 当 Refresh Token 无效、过期或被撤销时，返回：

```json
{
  "code": 2001,
  "message": "invalid or expired refresh token",
  "data": null
}
```

## 3. 联调建议

### 3.1 请求头建议

如果前端使用 JSON 接口，建议统一设置：

```http
Content-Type: application/json
```

刷新接口需要使用：

```http
Content-Type: text/plain
```

### 3.2 推荐调用顺序

1. 先调用 `POST /api/auth/code/send` 获取验证码。
2. 再调用 `POST /api/auth/login` 完成登录。
3. Access Token 过期后，调用 `POST /api/auth/refresh` 获取新的 Access Token。

### 3.3 服务器地址

当前后端默认启动在：

```text
http://localhost:8081
```

如果你修改了 `application.yaml` 中的 `server.port`，请同步更新前端请求地址。
