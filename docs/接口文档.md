## 1. 通用说明

### 1.1 统一响应格式

所有业务接口均返回 `ApiResponse<T>`：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | 业务状态码，`0` 表示成功 |
| message | string | 提示信息 |
| data | object / array / null | 业务数据 |

> 说明：部分鉴权失败场景 HTTP 状态码为 `401` / `403`，响应体仍为上述 JSON 结构（见 §1.2）。

### 1.2 错误码

#### 业务接口（HTTP 200，看 `code` 字段）

| code | message | 说明 |
| --- | --- | --- |
| 0 | success | 成功 |
| 1001 | invalid credentials or code | 登录失败：账号密码错误或验证码无效 |
| 1002 | 具体异常信息 | 参数错误、发码/登录限流等 |
| 2001 | invalid or expired refresh token | Refresh Token 无效、过期、已撤销或 hash 不匹配 |

`1002` 常见 message 示例：

| message | 场景 |
| --- | --- |
| 发送太频繁，请稍后再试 | 同一 target 60 秒内重复发码 |
| 该账号发送次数过多，请稍后再试 | 同一 target 1 小时内超过 5 次 |
| IP 发送次数过多，请稍后再试 | 同一 IP 1 小时内超过 10 次 |
| 登录失败次数过多，请15分钟后再试 | 连续登录失败达到 5 次 |
| loginType required | 未传 loginType |

#### 鉴权接口（HTTP 401 / 403）

受保护接口（如 `GET /api/user/me`）鉴权失败时，HTTP 状态码非 200，响应体示例：

```json
{
  "code": 2002,
  "message": "token expired",
  "data": null
}
```

| code | HTTP | message | 说明 |
| --- | --- | --- | --- |
| 2002 | 401 | token expired | Access Token 已过期 |
| 2003 | 401 | missing or invalid authorization header / invalid token / unauthorized | Token 缺失、格式错误或无效 |
| 2004 | 401 | session revoked or not found | Session 已撤销或不存在 |
| 2005 | 401 | user disabled or not found | 用户不存在或已禁用 |
| 2006 | 401 | token revoked | Access Token 已拉黑（logout 后） |
| 3001 | 403 | access denied | 已登录但无权限（角色不足） |

### 1.3 认证方式

#### 公开接口（无需 Token）

- `POST /api/auth/code/send`
- `POST /api/auth/login`
- `POST /api/auth/refresh`
- `POST /api/auth/logout`

#### 受保护接口（需要 Access Token）

请求头：

```http
Authorization: Bearer <accessToken>
```

当前受保护接口均需 `Authorization: Bearer <accessToken>`，普通用户需 `USER` 角色，管理接口需 `ADMIN` 角色。详见 §5 接口一览。

### 1.4 Token 说明

| Token | 格式 | 有效期（默认） | 用途 |
| --- | --- | --- | --- |
| accessToken | JWT 字符串 | 7200 秒（2 小时） | 访问受保护 API |
| refreshToken | `{jti}:{随机串}` | 7 天 / 记住登录 30 天 | 仅用于 `POST /api/auth/refresh` |

JWT Payload 主要字段：`sub`（userId）、`username`、`sid`（sessionId）、`roles`、`jti`、`exp`。

**重要：**

- 每次调用 `/refresh` 成功后，会返回**新的** `accessToken` 和**新的** `refreshToken`，前端必须覆盖保存。
- `logout` 后当前 Access Token 会被拉黑，Refresh 对应 Session 会被撤销。

### 1.5 登录类型 `loginType`

| loginType | 说明 |
| --- | --- |
| `password` | 账号密码登录 |
| `qq_email_code` | 邮箱验证码登录（SMTP 发邮件） |
| `phone_code` | 手机验证码登录（当前为 demo，验证码仅存 Redis） |

### 1.6 内置测试账号

| 用户名 | 密码 | 角色 | 初始余额 |
| --- | --- | --- | --- |
| admin | 123456 | USER + ADMIN | 100.00 |

## 2. 认证接口（AuthController）

### 2.1 发送验证码

- **URL**：`POST /api/auth/code/send`
- **Content-Type**：`application/json`
- **鉴权**：不需要

#### 请求参数（SendCodeRequest）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| loginType | string | 是 | `qq_email_code` 或 `phone_code` |
| target | string | 是 | 邮箱或手机号 |
| scene | string | 是 | 场景，登录传 `login` |

#### 请求示例

```json
{
  "loginType": "qq_email_code",
  "target": "user@qq.com",
  "scene": "login"
}
```

#### 成功响应

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "expiresIn": 300
  }
}
```

| 字段 | 说明 |
| --- | --- |
| expiresIn | 验证码有效期（秒），默认 300 |

#### 说明

- 验证码存储在 **Redis**，服务端只存哈希，**响应体不返回验证码明文**。
- 邮箱登录时验证码通过邮件发送；手机登录当前为 demo 实现，需自行从 Redis/日志获取验证码联调。
- 限流规则见 §1.2 中 `1002` 说明。

---

### 2.2 登录

- **URL**：`POST /api/auth/login`
- **Content-Type**：`application/json`
- **鉴权**：不需要

#### 请求参数（LoginRequest）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| loginType | string | 是 | `password` / `qq_email_code` / `phone_code` |
| rememberMe | boolean | 否 | 是否记住登录，默认 `false` |
| account | string | 条件必填 | 密码登录时必填 |
| password | string | 条件必填 | 密码登录时必填 |
| target | string | 条件必填 | 验证码登录时必填（邮箱或手机号） |
| code | string | 条件必填 | 验证码登录时必填 |

#### 请求示例

**账号密码登录：**

```json
{
  "loginType": "password",
  "account": "admin",
  "password": "123456",
  "rememberMe": true
}
```

**邮箱验证码登录：**

```json
{
  "loginType": "qq_email_code",
  "target": "user@qq.com",
  "code": "123456",
  "rememberMe": false
}
```

**手机验证码登录：**

```json
{
  "loginType": "phone_code",
  "target": "13800138000",
  "code": "123456",
  "rememberMe": false
}
```

#### 成功响应（LoginResponse）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| accessToken | string | JWT Access Token |
| refreshToken | string | Refresh Token，格式 `{jti}:{secret}` |
| expireIn | long | Access Token 有效期（秒），默认 7200 |
| userInfo | object | 当前用户信息 |

`userInfo` 字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | long | 用户 ID |
| username | string | 用户名 |
| roles | string[] | 角色列表，如 `["USER","ADMIN"]` |
| balance | decimal | 账户余额（购书支付用，默认 100.00） |

#### 响应示例

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiJ9...",
    "refreshToken": "a1b2c3d4-e5f6-7890-abcd-ef1234567890:f9e8d7c6-b5a4-3210-fedc-ba9876543210",
    "expireIn": 7200,
    "userInfo": {
      "id": 1,
      "username": "admin",
      "roles": ["USER"]
    }
  }
}
```

#### 失败响应示例

```json
{
  "code": 1001,
  "message": "invalid credentials or code",
  "data": null
}
```

#### 业务说明

- 验证码登录成功后，Redis 中对应验证码会被消费（删除）。
- 验证码登录时若用户不存在，会自动注册并绑定 `auth_user_identity`。
- 密码登录使用 BCrypt 校验 `auth_user.password_hash`。
- `rememberMe=true` 时 Refresh Token 有效期为 **30 天**，否则 **7 天**。
- 连续登录失败 5 次，15 分钟内锁定（按 account 或 target 计）。

### 2.3 刷新 Token

- **URL**：`POST /api/auth/refresh`
- **Content-Type**：`text/plain`
- **鉴权**：不需要

#### 请求体

直接传 **Refresh Token 字符串**（非 JSON）：

```text
a1b2c3d4-e5f6-7890-abcd-ef1234567890:f9e8d7c6-b5a4-3210-fedc-ba9876543210
```

#### 成功响应

结构与登录相同，返回**新的** `accessToken` 和**新的** `refreshToken`（Rotation）。

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiJ9...",
    "refreshToken": "新jti:新secret",
    "expireIn": 7200,
    "userInfo": {
      "id": 1,
      "username": "admin",
      "roles": ["USER"]
    }
  }
}
```

#### 失败响应

```json
{
  "code": 2001,
  "message": "invalid or expired refresh token",
  "data": null
}
```

#### 说明

- 采用 **Refresh Token Rotation**：旧 Session 作废，新建 Session。
- 每次刷新会重新计算 Refresh 滑动过期时间（7/30 天），但不超过 **绝对会话上限**（默认 90 天，自首次登录起算，refresh 不延长）。
- 超过绝对上限后 `/refresh` 与受保护 API 均返回失败，需重新登录。
- 若使用**已撤销**的旧 Refresh Token 刷新，会触发重放检测，撤销该用户全部 Session。

---

### 2.4 登出

- **URL**：`POST /api/auth/logout`
- **Content-Type**：`text/plain`（Refresh Token 可选放在 Body）
- **鉴权**：公开接口（不强制带 Token，但建议带 Access Token）

#### 请求头（可选）

```http
Authorization: Bearer <accessToken>
```

#### 请求体（可选）

传 Refresh Token 字符串，用于 Access Token 已过期时仍能撤销 Session：

```text
a1b2c3d4-...:f9e8d7c6-...
```

#### 成功响应

```json
{
  "code": 0,
  "message": "success",
  "data": null
}
```

#### 说明

- 若 Access Token 有效：解析 JWT → 拉黑 `jti` → 撤销对应 Session。
- 若 Access Token 无效/过期：仍可通过 Body 中的 Refresh Token 撤销 Session。
- 前端应在 logout 成功后清除本地保存的 Token。

## 3. 用户接口（UserController）

### 3.1 获取当前用户信息

- **URL**：`GET /api/user/me`
- **鉴权**：需要 `Authorization: Bearer <accessToken>`，且具备 `USER` 角色

#### 请求示例

```http
GET /api/user/me HTTP/1.1
Host: localhost:8081
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```

#### 成功响应

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": 1,
    "username": "admin",
    "roles": ["USER", "ADMIN"],
    "balance": 100.00
  }
}
```

#### 失败响应

见 §1.2 鉴权错误码（2002～2006、3001）。

> 说明：登录响应 `userInfo` 可能不含 `balance`；完整余额以 `/api/user/me` 为准。

## 4. 联调建议

### 4.1 Content-Type 汇总

| 接口 | Content-Type |
| --- | --- |
| `/api/auth/code/send` | `application/json` |
| `/api/auth/login` | `application/json` |
| `/api/auth/refresh` | `text/plain` |
| `/api/auth/logout` | `text/plain`（Body 可选） |
| `/api/user/me` | 无 Body，需 `Authorization` 头 |

### 4.2 推荐调用顺序

```text
1. POST /api/auth/code/send     （验证码登录时）
2. POST /api/auth/login         → 保存 accessToken + refreshToken
3. GET  /api/user/me            → Header 带 Bearer accessToken
4. POST /api/auth/refresh       → Access 过期时，Body 传 refreshToken
5. POST /api/auth/logout        → 清除 Token
```

### 4.3 前端 Token 存储建议

- `accessToken`：内存或 sessionStorage（敏感接口每次携带）。
- `refreshToken`：可存 localStorage；收到新 Token 后**立即覆盖**旧值。
- Access 返回 401 且 `code=2002` 时，调用 `/refresh`；若 `code=2001` 则跳转登录页。

### 4.4 配置项参考（application.yaml）

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| server.port | 8081 | 服务端口 |
| auth.jwt.access-expire-seconds | 7200 | Access 有效期 |
| auth.jwt.refresh-expire-days | 7 | Refresh 有效期 |
| auth.jwt.refresh-expire-days-remember | 30 | 记住登录 Refresh 滑动有效期 |
| auth.jwt.session-absolute-expire-days | 90 | 会话绝对最长有效期（首次登录起算） |
| auth.verification-code-ttl-seconds | 300 | 验证码 TTL |
| auth.rate-limit.send-code-per-target-seconds | 60 | 发码最小间隔 |
| auth.rate-limit.login-fail-max | 5 | 登录失败上限 |
