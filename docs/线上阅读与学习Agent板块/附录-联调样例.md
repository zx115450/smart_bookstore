## 演示脚本：试看 → 借阅解锁 → 归还 / 逾期回试看

前置：`BOOK_ID` 已绑 `ebook`（`ebook_book.book_id`）、至少 3 章且第 3 章非试看；USER / ADMIN JWT 已拿到。

```bash
BASE=http://localhost:8081
# export USER_JWT=... ADMIN_JWT=... BOOK_ID=... EBOOK_ID=... REF_ID=...（可选视频）

echo "=== A. 未借：试看章可读，付费章 5103 ==="
curl -s -H "Authorization: Bearer $USER_JWT" "$BASE/api/reader/ebooks/$EBOOK_ID/chapters/1" | head -c 200; echo
curl -s -H "Authorization: Bearer $USER_JWT" "$BASE/api/reader/ebooks/$EBOOK_ID/chapters/3"
# 期望 code=5103

if [ -n "$REF_ID" ]; then
  curl -s -H "Authorization: Bearer $USER_JWT" "$BASE/api/books/$BOOK_ID/media/$REF_ID/play"
  # 期望 preview=true
fi

echo "=== B. 申请借阅 + ADMIN 确认 → BORROWED 解锁 ==="
ORDER_JSON=$(curl -s -H "Authorization: Bearer $USER_JWT" -H "Content-Type: application/json" \
  -d "{\"bookId\":$BOOK_ID}" -X POST "$BASE/api/borrow/orders")
echo "$ORDER_JSON"
ORDER_ID=$(echo "$ORDER_JSON" | sed -n 's/.*"id"[: ]*\([0-9]*\).*/\1/p' | head -1)

curl -s -H "Authorization: Bearer $ADMIN_JWT" -X POST "$BASE/api/admin/borrow/orders/$ORDER_ID/confirm"
curl -s -H "Authorization: Bearer $USER_JWT" "$BASE/api/reader/ebooks/$EBOOK_ID/chapters/3"
# 期望 200 有正文

if [ -n "$REF_ID" ]; then
  curl -s -H "Authorization: Bearer $USER_JWT" "$BASE/api/books/$BOOK_ID/media/$REF_ID/play"
  # 期望 preview=false
fi

echo "=== C. 归还 → 立刻回试看 ==="
curl -s -H "Authorization: Bearer $USER_JWT" -X POST "$BASE/api/borrow/orders/$ORDER_ID/return"
# 或 ADMIN: POST /api/admin/borrow/orders/$ORDER_ID/return
curl -s -H "Authorization: Bearer $USER_JWT" "$BASE/api/reader/ebooks/$EBOOK_ID/chapters/3"
# 期望再次 5103

echo "=== D. 逾期停权（可选，需再借一次）==="
# 1) 再走一遍 apply + confirm 得到新 ORDER_ID
# 2) 把 due_at 拨到过去（MySQL），等 BorrowOverdueScheduler 扫到，或重启后等下一轮：
#    UPDATE borrow_order SET due_at = DATE_SUB(NOW(), INTERVAL 1 MINUTE) WHERE id = <ORDER_ID>;
# 3) 状态变 OVERDUE 后：
# curl -s -H "Authorization: Bearer $USER_JWT" "$BASE/api/reader/ebooks/$EBOOK_ID/chapters/3"
# 期望 5103（逾期不再解锁；已购 PAID 不受影响）
```

规则摘要：`BORROWED` 解锁全文；`OVERDUE` / `RETURNED` / `APPLIED` 仅试看；`PAID` 永久全文。

真实 DOCUMENT 链路仍由媒资 internal 完成；书城只代领凭证。分片大文件可用媒资：

```text
POST /internal/medias/upload-signature/multipart
POST /internal/medias/uploads/{fileId}/complete
```

（书城 Client 可后补封装，md 小文件不必强依赖。）

## HTTP / 业务码（阅读模块）

| 码 | 场景 |
| --- | --- |
| 5101 | 电子书不存在 / 下架 |
| 5103 | 试看拒绝（不调媒资） |
| 5201 | 笔记无权 |
| 5301 | Agent 限流 |
| 6002 | 媒资不可用 |
| 6003 | 章对象不存在或未切完 |

客服占用 `5001～5099`，阅读模块不要再用。

**不要**把媒资 401 / 400 原样透出；由 Client 映射为上表。

## 板块自测清单（可全 Mock）

```text
1. 登录 USER
2. sync-chapters 后目录 ≥ 3，第 3 章 locked
3. GET 第 1 章有正文；GET 第 3 章 5103
4. 划线笔记；用户 B 改 A 失败
5. Agent 总结第 2 章 → AI_SUMMARY；改短 → AI_REWRITE
6. mock=false 时用媒资 fileId 重复 2～3
7. B6：试看 play → 借阅完整播 → 归还恢复
8. 逾期 OVERDUE 后付费章 5103（已购除外）
9. /api/ai/chat：问「第三章为什么打不开」「有没有电子书」走 FAQ/查书 Tool
```
