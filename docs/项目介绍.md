## 一、项目简介

**智慧书城**是在 `smart_bookstore` 工程基础上演进而来的后端项目。它以「到馆阅读」与「图书流通」为主线，将座位预约、签到打卡、借书、购书、优惠券与秒杀串联成一条完整的业务闭环。

项目采用 **四层架构**（Controller → Service → Repository → Entity），模块按业务域分包，统一 JWT 鉴权与错误码体系，便于分阶段迭代与演示。

**一句话定位**：在统一认证平台上，实现 **到馆阅读（预约 + 签到）** 与 **图书流通（借 / 买）** 及 **营销（券 / 秒杀）** 的闭环。

---

## 二、业务闭环

```text
登录（密码 / 验证码 / QQ OAuth）
    ↓
预约自习室座位（行锁防超卖）
    ↓
到馆扫码签到（BitMap 连续签到，满 7 天赠券）
    ↓
┌─────────────────┬─────────────────┐
│  浏览图书        │  申请借阅        │
│  Redis 缓存详情  │  馆员确认借出    │
│  购物车下单      │  到期归还 / 逾期 │
│  用券余额支付    │                  │
└─────────────────┴─────────────────┘
    ↓
优惠券秒杀（Redis Lua + RabbitMQ 异步落库）
```

## 五、技术亮点

### 5.1 并发与一致性

- **座位防超卖**：`SELECT ... FOR UPDATE` 行锁 + 占用校验，精确到「时段 × 座位」粒度
- **借阅库存**：申请阶段校验占用数，确认借出时事务内扣减 `borrow_stock`
- **购书支付**：事务内扣余额、减 `sale_stock`，配合幂等键防重复下单
- **秒杀抢券**：Redis Lua 脚本原子扣库存 + Set 一人一单 + DB 唯一索引兜底

### 5.2 缓存设计

- **图书详情**：Cache-Aside，TTL 加随机抖动防雪崩，更新时主动失效
- **布隆过滤器**：拦截不存在图书 ID 的穿透查询
- **签到 BitMap**：Redis 按用户按月存储签到记录，高效统计连续天数

### 5.3 消息队列

- **秒杀**：抢券成功后发 MQ，Consumer 异步写入 `seckill_order` 与 `user_coupon`
- **订单超时**：延迟队列触发未支付订单自动取消，死信队列兜底异常

### 5.4 认证与安全

- **双 Token**：Access Token 短期有效，Refresh Token 可轮换，支持 Remember Me
- **限流**：发码频率、登录失败锁定、IP 维度限制
- **RBAC**：Spring Security `@PreAuthorize` 按角色控制接口

### 5.5 架构规范

- 统一响应体 `{ code, message, data }`
- 模块化异常与错误码（1xxx 认证、3xxx 预约、4xxx 书城等）
- 工厂模式扩展登录方式、验证码发送渠道、优惠券计算策略

## 七、快速开始

### 7.1 环境要求

```text
JDK 21+
MySQL 8.0（库名 smart_bookstore，可由 schema.sql 自动建表）
Redis 6+
RabbitMQ 3.x（秒杀、订单超时取消需要）
Maven 3.8+
```

### 7.2 配置说明

编辑 `src/main/resources/application.yaml`，至少配置：

| 配置项 | 说明 |
|--------|------|
| `spring.datasource.*` | MySQL 连接信息 |
| `spring.data.redis.*` | Redis 地址（可用环境变量 `REDIS_HOST` 等覆盖） |
| `spring.rabbitmq.*` | RabbitMQ 连接信息 |
| `auth.jwt.secret` | JWT 密钥（生产环境务必更换） |
| `auth.oauth.qq.*` | QQ 登录（可选，通过环境变量 `QQ_APP_ID` 等配置） |

### 7.3 启动

```bash
# 克隆项目后进入目录
mvn spring-boot:run
```

服务默认监听 **8081** 端口。启动时会执行 `classpath:db/schema.sql` 初始化表结构与种子数据。

### 7.4 验证

1. 使用 Postman / Apifox 调用 `POST /api/auth/login` 获取 Token  
2. 携带 `Authorization: Bearer <access_token>` 访问业务接口  
3. 完整接口清单见 [接口文档](./接口文档.md)
