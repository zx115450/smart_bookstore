# 测试板块分步实现指南


> **项目**：smart_bookstore（智慧书城） · **文档类型**：学习文档  
> **关联**：`src/test` — T0～T6 测试补齐  
> **索引**：[学习文档中心](./README.md)

本指南将测试建设拆成 T0～T6，按依赖顺序推进。目标是：**CI 可稳定跑通、不依赖真模型 / 真邮件、核心业务可回归**。

当前仓库已具备部分单测与 `application-test.yaml`；下列「现状」会随代码演进变化，以目录 `src/test/java` 为准。

---

## 总览

| 阶段 | 主题 | 类型 | 依赖中间件 |
| --- | --- | --- | --- |
| T0 | 测试基线与配置 | 工程 | 否 |
| T1 | 纯逻辑 / 工具类 | 单元 | 否 |
| T2 | 认证与 JWT | 单元 | 否 |
| T3 | 书城交易核心 | 单元（Mock 仓储） | 否 |
| T4 | AI 工具与推荐 | 单元（Mock） | 否 |
| T5 | Web / Security 切片 | `@WebMvcTest` 等 | 否 |
| T6 | 集成测试 | `*IT` + Testcontainers | 是 |

运行命令：

```bash
# 全部测试
mvn test

# 仅单元测试（排除集成测命名）
mvn -Dtest='!*IT' test

# 仅某个类
mvn -Dtest=JwtServiceTest test
```

## T0：测试基线与配置

### 目标

- 测试 profile 不连真实 MySQL / Redis / RabbitMQ / Milvus
- 不调用真实 LLM、不发真实邮件
- Surefire 可重复执行

### 已有参考

- `src/test/resources/application-test.yaml`
- `pom.xml` 中 `spring-boot-starter-test`、`testcontainers-*`

### 建议完成项

1. 默认单测使用 `@ActiveProfiles("test")` 或测试专用配置
2. `spring.sql.init.mode=never`（IT 自行控制建表）
3. 禁用 / Mock 邮件与 AI 自动配置
4. 修正无断言的烟雾测试（如 `SmartBookstoreApplicationTests`），避免「假绿」

### 完成标准

- `mvn -Dtest='!*IT' test` 在无本地中间件时可通过

---

## T1：纯逻辑与枚举

### 目标

无 Spring 容器，测状态机、折扣计算、文档拼装等纯函数逻辑。

### 建议用例

| 类 | 关注点 |
| --- | --- |
| `CouponDiscountCalculator` 及实现 | 满减 / 折扣边界、金额精度 |
| `BorrowOrderStatus` 等枚举 | 合法迁移、非法迁移拒绝 |
| `FaqDocumentBuilder` / `BookDocumentBuilder` | 字段拼接、空值处理 |
| `FaqTool` 关键词匹配 | 命中 / 未命中 |

### 现状参考

- `CouponDiscountCalculatorTest`
- `BorrowOrderStatusTest`
- `FaqDocumentBuilderTest`、`BookDocumentBuilderTest`
- `FaqToolKeywordTest`

### 完成标准

- 关键业务规则有「正常 + 边界 + 非法输入」三类断言

---

## T2：认证与 JWT

### 目标

验证 Token 签发 / 解析 / 拒绝错误签名；登录处理器可用 Mockito 测分支。

### 建议用例

| 场景 | 断言 |
| --- | --- |
| 签发 Access Token | 解析后 `userId` / `roles` / `sessionId` 正确 |
| 非法 Token | 抛出约定异常 |
| 过期（可选） | 使用短过期配置验证拒绝 |
| `LoginHandlerFactory` | 未知 `loginType` 抛错；已知类型路由正确 |

### 现状参考

- `JwtServiceTest`（Mockito + `@ExtendWith(MockitoExtension.class)`）

### 完成标准

- JWT 与至少一种登录 Handler（如密码 / 邮箱验证码）有单测

---

## T3：书城交易核心（Mock 仓储）

### 目标

不启容器或仅轻量注入，用 Mock Repository 覆盖借阅、下单、优惠券核销主路径。

### 建议用例

| 服务 | 场景 |
| --- | --- |
| `BorrowService` | 申请 → 借出 → 归还；库存不足失败 |
| `TradeService` | 创建订单、幂等键重复返回同一单、优惠券折扣 |
| `SeckillService`（可后置） | Lua 成功 / 售罄 / 已参与的分支（Mock Redis 层） |

### 现状参考

- `BorrowServiceTest`、`TradeServiceTest`

### 完成标准

- 下单与借阅的主成功路径 + 至少 2 个失败路径有测试

---

## T4：AI 工具与推荐（Mock，不调真模型）

### 目标

CI 内 **禁止** 依赖真实 DeepSeek / 通义 API。

### 建议用例

| 组件 | 场景 |
| --- | --- |
| `BookRecommendService` | EXPLORE / LEARN / PERSONALIZED；未登录个性化返回空 |
| Tool 视图 / 组装 | 工具返回 JSON 字段完整 |
| （可选）`ChatClient` | Mock Builder，断言注册了预期 Tool（偏配置测） |

### 现状参考

- `BookRecommendServiceTest`

### 完成标准

- 推荐主意图有覆盖；PERSONALIZED 未登录行为明确断言
- 文档中写明：效果评测（真人 / Prompt）与单测分离

---

## T5：Web 与 Security 切片测试

### 目标

用 `@WebMvcTest` + `spring-security-test` 验证鉴权与入参校验，不启完整业务。

### 建议用例

| 接口 | 场景 |
| --- | --- |
| `/api/auth/login` | 参数缺失 → 4xx |
| `/api/admin/**` | 无 Token / USER 角色 → 401 / 403；ADMIN → 进入 Controller |
| `/api/ai/chat` | `permitAll` 可匿名访问 |

### 完成标准

- 至少覆盖「匿名可访问」「需登录」「需 ADMIN」三类 Matcher 行为

---

## T6：集成测试（`*IT` + Testcontainers）

### 目标

真实中间件上验证跨组件行为。类名建议以 `IT` 结尾，便于 Surefire 筛选。

### 建议用例（按优先级）

1. **AuthIT**：发码（Mock 邮件）→ 登录 → refresh → logout，会话落库 / Redis
2. **BorrowIT**：完整借阅状态流转 + DB 断言
3. **TradeTimeoutIT**：下单 → 超时消息 → 取消 / 释券
4. **SeckillIT**：并发抢券，断言库存与一人一单
5. **ReservationIT**：乐观锁冲突（两用户抢同一座位时段）

### 技术要点

```java
// 示意：动态注入容器地址
@DynamicPropertySource
static void registerProps(DynamicPropertyRegistry registry) {
    registry.add("spring.datasource.url", MYSQL::getJdbcUrl);
    registry.add("spring.data.redis.host", REDIS::getHost);
    // ...
}
```

- 使用 `schema.sql` 或 Testcontainers 启动后执行迁移
- 并发用例注意超时与可重复性（固定随机种子或唯一活动 ID）

### 完成标准

- 本地 Docker 可用时，`mvn -Dtest='*IT' test` 可通过
- CI 可选：无 Docker 时跳过 IT（profile 或 JUnit condition）

