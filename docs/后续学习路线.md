# 后续学习路线


> **项目**：smart_bookstore（智慧书城） · **文档类型**：学习文档  
> **关联**：`learning/` — 项目结束后的加深计划  
> **索引**：[学习文档中心](./README.md)

本文档面向「智慧书城」项目阶段性结束后的能力进阶，强调 **补短板 → 加深现有亮点 → 按兴趣横向扩展**，避免为学而学再写一个同款商城。

---

## 原则

1. 优先补本项目已暴露的短板（测试、安全、数据演进）
2. 把秒杀、MQ、AI Tool / RAG 做成「能讲清失败与验证」的案例
3. 横向扩展只选 1～2 条，做深比做广更有复利

---

## 一、优先补：项目里仍薄的部分

### 1. 测试与工程质量

- 单元测试：Mockito 隔离 Service / 计算器 / JWT
- 集成测试：Testcontainers（MySQL / Redis / RabbitMQ）
- 接口或契约测试（可选）

目标：改秒杀、下单、JWT 时敢重构。  
实操见 [测试板块分步实现指南](./测试板块分步实现指南.md)。

### 2. 安全与配置治理

- 密钥外置（环境变量 / 密钥管理），清理默认 JWT secret
- Actuator 最小暴露与鉴权
- OAuth 回调校验、接口限流

对照 [IMPROVEMENTS.md](../IMPROVEMENTS.md) 的 P0 逐项落实。

### 3. 数据演进

- 引入 Flyway 或 Liquibase
- 索引与慢查询、事务边界
- 幂等与最终一致性（订单、秒杀发券）

## 三、可选扩展（按兴趣选 1～2 条）

- **微服务 / 拆分**：Gateway + 认证独立 + 订单 / 库存拆分（先理解分布式事务代价）
- **可观测性**：OpenTelemetry 链路 + 业务指标 + 告警（仓库已有 Prometheus 骨架）
- **前端全栈**：按 [前端部署指南](./前端部署指南.md) 完成同域反代与 OAuth 闭环
- **云原生**：Docker Compose 一键起全栈 → 再学 K8s 探针与滚动发布
- **推荐进阶**：协同过滤、向量检索调参（当前个性化偏规则）

---

## 四、不建议一上来就冲的

- 再写一个功能同质的「万能商城」却不补测试
- 无监控、无测试时全面微服务化
- 盲目追新模型 / 新框架，而核心业务路径仍无自动化回归

---

## 五、3～6 个月务实计划

### 第 1 个月

- 为核心路径补单测，并完成 1～2 个 Testcontainers 集成测
- 清理敏感配置，密钥全部外置

### 第 2～3 个月

- 对秒杀 / 下单做压测与失败场景记录（超卖、MQ 丢失、重复消费）
- 可选：Flyway 迁移、Actuator 收紧

### 第 4～6 个月（二选一做深）

- **偏后端工程**：可观测性 + 限流网关 + 部署流水线
- **偏 AI**：RAG / Tool 评测集 + 推荐效果对比实验

---

## 六、能力自检清单

完成一段时间学习后，可用下列问题自检：

- [ ] 能否在不连真模型的情况下测通 AI Tool 路径？
- [ ] 秒杀超卖与一人多单是否有自动化或压测证据？
- [ ] 生产配置是否可以「零明文密钥」启动？
- [ ] 数据库变更是否可版本化回放？
- [ ] 能否用 3 分钟讲清：下单超时取消、秒杀 Lua + MQ、推荐召回降级？
