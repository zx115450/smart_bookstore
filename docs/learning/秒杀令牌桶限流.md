# 秒杀入口令牌桶限流


> **项目**：smart_bookstore（智慧书城） · **文档类型**：学习文档（加深分册）  
> **索引**：[加深方向](./README.md) · [学习文档中心](../README.md)

本文说明智慧书城秒杀 `grab` 的 **Redis Lua 令牌桶**（方案 B）如何工作、如何配置与验证。

---

## 目标

在库存 Lua **之前**限制进入抢券热路径的 QPS，保护 Redis / MQ / 应用线程；未拿到令牌时 **不扣库存、不进已抢 Set**。

与库存逻辑分工：

| 层 | 职责 |
| --- | --- |
| 令牌桶 | 准入：太火爆则快速失败 |
| 库存 Lua | 正确性：不超卖、一人一单（热路径） |
| DB 唯一键 | 最终一人一单 |

---

## 调用顺序

```text
grab
  → 校验活动 / 幂等（已有结果则直接返回，不耗令牌）
  → SeckillRateLimitService.assertAllowed（活动桶 → 用户桶）
  → seckill_grab.lua 扣库存
  → 发 MQ → PROCESSING
```

相关代码：

- Lua：`src/main/resources/lua/seckill_token_bucket.lua`
- 服务：`SeckillRateLimitService`
- 配置：`SeckillRateLimitProperties`（`bookstore.seckill.rate-limit`）
- 挂载点：`SeckillService.grab`
- 错误码：`SECKILL_RATE_LIMITED`（4508），文案「活动太火爆，请稍后再试」

---

## 算法

桶状态存在 Redis Hash：

```text
Key:  seckill:bucket:act:{activityId}
      seckill:bucket:act:{activityId}:user:{userId}
Field: tokens, last_ms
```

每次 `tryAcquire`（Lua 内原子执行）：

1. 读 `tokens`、`last_ms`；若无 Key，视为满桶 `tokens=capacity`，`last_ms=now`
2. `tokens = min(capacity, tokens + (now - last_ms) * refillPerSecond / 1000)`
3. 若 `tokens >= 1`：减 1，写回，返回 `1`
4. 否则写回补充后的 tokens，返回 `0`

`assertAllowed`：先活动桶，再用户桶；任一为 `0` 即抛 `rateLimited()`。

## 配置

`application.yaml`：

```yaml
bookstore:
  seckill:
    rate-limit:
      enabled: true
      activity-capacity: 2000
      activity-refill-per-second: 2000
      user-capacity: 2
      user-refill-per-second: 1
      key-ttl-seconds: 7200
```

| 项 | 含义 |
| --- | --- |
| `activity-capacity` | 活动桶容量（短时突发上限） |
| `activity-refill-per-second` | 活动桶每秒补充 |
| `user-capacity` / `user-refill-per-second` | 单用户防刷 |
| `key-ttl-seconds` | 限流 Key TTL，避免冷活动占内存 |
| `enabled: false` | 关闭限流（压测库存 Lua 时可临时关掉） |

调参建议：活动桶略高于「可持续处理的 grab QPS」；用户桶保持很小（如 2/秒），避免同一账号打爆。

## 与网关限流的关系

本实现是 **应用内、按 activityId / userId** 的细粒度限流。  
Nginx `limit_req` 等仍可做 **IP / 全路径** 粗限流，两者叠加：

```text
网关（IP）→ 应用令牌桶（活动+用户）→ 库存 Lua
```

## 已知边界

1. 多实例共享同一 Redis 桶，行为正确；不要用单机 Guava 替代分布式桶。
2. 时钟回拨时 Lua 将负间隔当作 0，不倒扣。
3. 令牌已消耗但后续 Lua 售罄：属于「花了限流名额但没抢到」，可接受；不要为售罄回滚令牌（实现复杂且意义有限）。
4. 关闭 `enabled` 后无限流，仅依赖库存 Lua。
