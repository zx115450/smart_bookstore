---

## 亮点

### 1. AI 落地务实

- System Prompt 约束「事实走 Tool、禁止编造」
- Tool Calling：查书、FAQ、个人借阅、推荐、阅读画像
- Redis 多轮会话记忆；RAG（Milvus）可开关，关闭时规则召回降级
- 推荐链路：多路召回 → 回查库存 / 架位 → 重排 → 生成理由

### 2. 高并发与一致性有章法

- 秒杀：Redis Lua 扣库存 → MQ 异步发券 → DB 唯一约束防一人多单
- 购书订单：幂等键、优惠券核销、超时取消（MQ / 死信）
- 预约：座位时段乐观锁控制并发

### 3. 工程习惯较好

- 域内分层（controller / service / repository / dto / exception）
- 统一响应与模块级异常处理
- 登录策略模式（`LoginHandlerFactory`）
- README 完整，并有 [IMPROVEMENTS.md](../IMPROVEMENTS.md) 自省清单

## 主要问题

| 维度 | 现状 | 影响 |
| --- | --- | --- |
| 安全 | `application.yaml` 存在明文 SMTP / DB 密码与 JWT 默认 secret；部分 Actuator 端点放行 | 泄露与伪造 Token 风险 |
| 测试 | 已有部分单测，覆盖仍薄；`*IT` / Testcontainers 集成测未成体系 | 重构与回归成本高 |
| 演进痕迹 | 如 `InMemoryUserRepository` 等遗留代码；多份手工 migration、无 Flyway | 可维护性与部署一致性不足 |
| 架构边界 | 单体承载 AI、交易、秒杀、预约 | Demo 合理；长期扩展需拆分或划清模块边界 |
